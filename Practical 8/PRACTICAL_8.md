# Practical 8: Query Processing and Optimization

## Aim / Problem Definition
To execute complex analytical queries on a large dataset (500,000 clickstream events), inspect execution plans using `EXPLAIN` and `EXPLAIN ANALYZE`, identify performance bottlenecks (such as correlated subqueries and redundant full-table scans), apply query optimizations, and compare before-and-after runtime. Furthermore, rewrite a nested correlated SQL query using Common Table Expressions (CTEs) and Window Functions, verifying logical equivalence.

## Tools / Technologies
- Python 3.13
- DuckDB (embedded vectorized analytical database engine)
- Pandas & NumPy (data generation and verification)
- SQL (`EXPLAIN`, CTEs, Window Functions `DENSE_RANK()`)

## Step-by-Step
1. **Generate Large Analytical Dataset**: Run `generate_clickstream.py` to synthesize 500,000 realistic e-commerce clickstream events (36.8 MB) containing `event_id`, `user_id`, `session_id`, `event_time`, `event_type`, `page_url`, `device`, `duration_sec`, and `purchase_amount`.
2. **Load into Vectorized Engine**: Load the dataset into DuckDB using `read_csv_auto()`.
3. **Capture Baseline Execution Plan**: Run an analytical purchase funnel query containing correlated subqueries and capture its query plan using `EXPLAIN`.
4. **Identify Bottleneck**: Observe that the baseline query evaluates correlated scalar subqueries and performs redundant passes over unindexed rows.
5. **Optimize Query**: Rewrite the query using CTEs, early filter pushdown, and single-pass hash joins.
6. **Compare Runtime and Plans**: Measure execution times, compare execution plan operators, and assert logical equivalence of results (`df_baseline == df_optimized`).
7. **Supplementary Nested Query Rewrite**: Rewrite an $O(N^2)$ correlated subquery ranking top sessions per device into a clean $O(N \log N)$ `DENSE_RANK() OVER (PARTITION BY ...)` window function.

## Key Questions

### 1. What information does an `EXPLAIN` execution plan provide to a data engineer?
An `EXPLAIN` plan displays the internal query tree generated by the query optimizer. It reveals whether the database is using a sequential full scan (`SEQ_SCAN`) or an index scan, the type of join algorithm selected (Hash Join, Nested Loop, or Merge Join), projection/filter pushdowns, and estimated or actual row counts passing between operators.

### 2. Why are correlated subqueries typically slower than CTEs or window functions?
A correlated subquery references columns from the outer query, meaning the database engine must theoretically evaluate the inner subquery repeatedly for every single candidate row from the outer query ($O(N^2)$ complexity). Conversely, CTEs and window functions allow the engine to compute intermediate aggregates in a single vectorized pass and partition data using efficient hashing or sorting ($O(N \log N)$).

### 3. How does filter pushdown improve query performance?
Filter pushdown moves `WHERE` clause condition evaluations as close to the storage layer as possible before joins and aggregations occur. By eliminating non-qualifying rows early, it drastically reduces the volume of data that must be loaded into memory, hashed, sorted, or joined downstream.

## Supplementary Problem: Nested Correlated Query Rewrite
**Requirement**: Rewrite the supplementary nested SQL query using a CTE or window function and verify baseline and optimized results are logically equivalent.

**Implementation & Result**:
- **Baseline**: A correlated subquery counting greater duration sessions for each device row:
  ```sql
  SELECT s1.device, s1.session_id, s1.max_duration
  FROM device_sessions s1
  WHERE (SELECT COUNT(DISTINCT s2.max_duration) FROM device_sessions s2 
         WHERE s2.device = s1.device AND s2.max_duration >= s1.max_duration) <= 3
  ORDER BY s1.device, s1.max_duration DESC;
  ```
- **Optimized (Window Function)**:
  ```sql
  WITH ranked_sessions AS (
      SELECT device, session_id, max_duration,
             DENSE_RANK() OVER (PARTITION BY device ORDER BY max_duration DESC) AS rank_pos
      FROM device_sessions
  )
  SELECT device, session_id, max_duration
  FROM ranked_sessions
  WHERE rank_pos <= 3
  ORDER BY device, max_duration DESC;
  ```
- **Result**: Execution time dropped from **791.47 ms** to **10.44 ms** (**75.83x speedup**), with 100% identical output records verified by automated assertion.

## Conclusion
Practical 8 demonstrated how execution plan analysis identifies query bottlenecks in analytical processing. By replacing nested correlated subqueries with modular CTEs and window functions (`DENSE_RANK()`), query runtime was reduced by up to 75x while guaranteeing identical analytical outputs.
